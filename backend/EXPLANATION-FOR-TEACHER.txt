🎯 ภาพรวมโปรเจกต์
==================

โปรเจกต์นี้เป็น Sleep App ที่ประกอบด้วย:
1. React Native Mobile App (Frontend)
2. Express.js Backend API (Backend)
3. Firebase Integration (Database & Authentication)

========================================
📊 สถานะการพัฒนาปัจจุบัน
========================================

✅ BACKEND API: สมบูรณ์ 100%
- Express.js Server พร้อมใช้งาน
- API Endpoints ครบทุกฟีเจอร์ (CRUD)
- Firebase Integration พร้อม
- Mock Database สำหรับการทดสอบ
- Authentication System

✅ REACT NATIVE APP: โครงสร้างพร้อม
- Component Architecture
- Screen Structure
- Navigation Setup
- State Management (Redux)

========================================
🔧 การทำงานของ Backend API
========================================

1. DATABASE SYSTEM
------------------
ปัจจุบันใช้ "Mock Database" เพราะ:
- Firebase Service Account Key ยังไม่ได้ตั้งค่าจริง
- ข้อมูลจะเก็บใน Memory (RAM) ชั่วคราว
- เมื่อ restart server ข้อมูลจะหายไป
- เหมาะสำหรับการทดสอบและ Demo

2. AUTHENTICATION SYSTEM
-------------------------
ใช้ Mock Token: "mock-token"
- ไม่ใช่ Firebase Authentication จริง
- เป็นระบบจำลองสำหรับการทดสอบ
- ใน Production จะใช้ Firebase ID Token จริง

3. API ENDPOINTS ที่ทำงานได้
-----------------------------
✅ Authentication APIs:
- POST /api/auth/register (สร้างโปรไฟล์ผู้ใช้)
- GET /api/auth/profile (ดูโปรไฟล์)
- PUT /api/auth/profile (แก้ไขโปรไฟล์)

✅ Users APIs:
- GET /api/users (ดูผู้ใช้ทั้งหมด)
- GET /api/users/:id (ดูผู้ใช้ตาม ID)

✅ Tasks APIs (CRUD):
- GET /api/tasks (ดูงานทั้งหมด)
- POST /api/tasks (สร้างงานใหม่)
- PUT /api/tasks/:id (แก้ไขงาน)
- DELETE /api/tasks/:id (ลบงาน)

✅ Games APIs:
- GET /api/games (ดูเกมทั้งหมด)
- GET /api/games/scores (ดูคะแนน)
- POST /api/games/:gameId/score (บันทึกคะแนน)

✅ Sleep APIs (CRUD):
- GET /api/sleep (ดูข้อมูลการนอน)
- POST /api/sleep (บันทึกการนอน)
- PUT /api/sleep/:id (แก้ไขข้อมูล)
- DELETE /api/sleep/:id (ลบข้อมูล)

========================================
❓ คำถามที่พบบ่อย
========================================

Q1: ข้อมูลเก็บที่ไหน?
A1: ตอนนี้เก็บใน Mock Database (Memory)
    - ไม่ได้เก็บใน Firebase จริง
    - เมื่อ restart server ข้อมูลหายไป
    - เหมาะสำหรับการทดสอบ

Q2: ทำไมไม่มี Login API?
A2: ใช้ Mock Authentication แทน
    - ใช้ token: "mock-token" สำหรับทดสอบ
    - ใน Production จะใช้ Firebase Auth จริง
    - Register API สร้างโปรไฟล์ใน Database

Q3: ข้อมูลแสดงใน Firebase หรือไม่?
A3: ไม่แสดง เพราะใช้ Mock Database
    - ต้องตั้งค่า Service Account Key จริง
    - เมื่อตั้งค่าแล้วจะเก็บใน Firestore

Q4: ทำไมสร้างบัญชีได้แค่ครั้งเดียว?
A4: เพราะใช้ Mock System
    - ข้อมูลเก็บใน Memory
    - User ID เป็น "mock-user-123" ตายตัว
    - ใน Production จะสร้างได้หลายบัญชี

🚀 วิธีการทดสอบ Backend

   ใช้ไฟล์ API-COMMANDS.txt
