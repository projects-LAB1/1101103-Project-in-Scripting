========================================
📋 ส่วนที่ 1: แนะนำ Backend API (1 นาที)
========================================

🎤 สคริปต์การพูด:
"ส่วนต่อไปผมจะอธิบายเกี่ยวกับ Backend API ที่เราพัฒนาขึ้นครับ"

📊 ข้อมูลที่ต้องบอก:
1. เทคโนโลยีที่ใช้: Express.js + Firebase
2. จำนวน API Endpoints: 14 endpoints
3. ฟีเจอร์หลัก: CRUD Operations ครบทุกระบบ
4. Database: Mock Database สำหรับ Demo

🎤 คำพูดแบบละเอียด:
"Backend API ของเราใช้ Express.js เป็น Framework หลัก เชื่อมต่อกับ Firebase สำหรับ Database และ Authentication ครับ 

เรามี API Endpoints ทั้งหมด 14 ตัว แบ่งเป็น 5 กลุ่มหลัก คือ Authentication, Users, Tasks, Games และ Sleep 

สำหรับการ Demo วันนี้ เราใช้ Mock Database ที่เก็บข้อมูลใน Memory เพื่อให้สะดวกในการทดสอบครับ"

📋 ส่วนที่ 2: Demo การทำงาน (3 นาที)
========================================

🔧 ขั้นตอนที่ 1: เริ่ม Server (30 วินาที)
------------------------------------------
🎤 พูด: "ตอนนี้ผมจะเริ่ม Server ครับ"

💻 คำสั่ง: npm run dev

🎤 พูด: "Server ทำงานที่ port 5000 แล้วครับ"

📊 ข้อมูลที่ต้องรู้:
- Port: 5000
- Framework: Express.js
- Database: Mock Database
- Authentication: Token-based

🔧 ขั้นตอนที่ 2: ทดสอบ Root API (15 วินาที)
--------------------------------------------
🎤 พูด: "เริ่มจากการทดสอบ API หลักครับ"

💻 เปิด Browser: http://localhost:5000/

🎤 พูด: "นี่คือข้อมูลภาพรวมของ API ทั้งหมดที่เรามี"

📊 ผลลัพธ์ที่จะเห็น:

  }

🔧 ขั้นตอนที่ 3: Authentication APIs (45 วินาที)
------------------------------------------------
🎤 พูด: "ระบบ Authentication มี 3 endpoints หลัก"

A) Register User (15 วินาที)
🎤 พูด: "เริ่มจากการสร้างบัญชีผู้ใช้"
💻 POST /api/auth/register
📊 Headers: Authorization: Bearer mock-token
📊 Body: {"displayName": "ผู้ใช้ทดสอบ", "phoneNumber": "0812345678"}
🎤 พูด: "สร้างบัญชีสำเร็จ ได้ User ID และข้อมูลโปรไฟล์"

B) Get Profile (15 วินาที)
🎤 พูด: "ดึงข้อมูลโปรไฟล์ผู้ใช้"
💻 GET /api/auth/profile
📊 Headers: Authorization: Bearer mock-token
🎤 พูด: "ได้ข้อมูลโปรไฟล์ครบถ้วน"

C) Update Profile (15 วินาที)
🎤 พูด: "แก้ไขข้อมูลโปรไฟล์"
💻 PUT /api/auth/profile
📊 Body: {"displayName": "ชื่อใหม่"}
🎤 พูด: "อัพเดทข้อมูลสำเร็จ"

🔧 ขั้นตอนที่ 4: Tasks APIs - CRUD (1 นาที)
-------------------------------------------
🎤 พูด: "ระบบจัดการงานมี CRUD operations ครบ"

A) Create Task (15 วินาที)
🎤 พูด: "สร้างงานใหม่"
💻 POST /api/tasks
📊 Body: {
  "title": "ออกกำลังกาย",
  "description": "วิ่ง 30 นาที", 
  "category": "health",
  "priority": "high"
}
🎤 พูด: "สร้างงานสำเร็จ ได้ Task ID"

B) Read Tasks (15 วินาที)
🎤 พูด: "ดูรายการงานทั้งหมด"
💻 GET /api/tasks
🎤 พูด: "ได้รายการงานของผู้ใช้"

C) Update Task (15 วินาที)
🎤 พูด: "อัพเดทสถานะงาน"
💻 PUT /api/tasks/{taskId}
📊 Body: {"completed": true}
🎤 พูด: "เปลี่ยนสถานะเป็นเสร็จแล้ว"

D) Delete Task (15 วินาที)
🎤 พูด: "ลบงาน"
💻 DELETE /api/tasks/{taskId}
🎤 พูด: "ลบงานออกจากระบบ"

🔧 ขั้นตอนที่ 5: Sleep APIs (30 วินาที)
---------------------------------------
🎤 พูด: "ระบบติดตามการนอนหลับ"

A) Create Sleep Record (15 วินาที)
💻 POST /api/sleep
📊 Body: {
  "bedTime": "2024-01-14T22:30:00Z",
  "wakeTime": "2024-01-15T06:30:00Z",
  "quality": 4,
  "notes": "นอนหลับสบาย"
}
🎤 พูด: "บันทึกข้อมูลการนอนสำเร็จ"

B) Read Sleep Data (15 วินาที)
💻 GET /api/sleep
🎤 พูด: "ดูประวัติการนอนของผู้ใช้"

🔧 ขั้นตอนที่ 6: Games APIs (30 วินาที)
---------------------------------------
🎤 พูด: "ระบบเกมฝึกสมอง"

A) Get Games (10 วินาที)
💻 GET /api/games
🎤 พูด: "ดูรายการเกมที่มี"

B) Record Score (10 วินาที)
💻 POST /api/games/memory-game/score
📊 Body: {"score": 1250, "level": 5}
🎤 พูด: "บันทึกคะแนนเกม"

C) Get Scores (10 วินาที)
💻 GET /api/games/scores
🎤 พูด: "ดูประวัติคะแนน"

========================================
❓ คำถามที่อาจถูกถาม + คำตอบ
========================================

Q1: "ทำไมใช้ Mock Database?"
A1: "เพื่อความสะดวกในการ Demo ครับ ไม่ต้องตั้งค่า Firebase ซับซ้อน แต่โครงสร้างพร้อมเชื่อมต่อ Firebase จริงแล้ว"

Q2: "ข้อมูลหายเมื่อ restart หรือไม่?"
A2: "ใช่ครับ เพราะเก็บใน Memory แต่ใน Production จะเก็บใน Firebase Firestore ถาวร"

Q3: "มี Authentication จริงหรือไม่?"
A3: "ตอนนี้ใช้ Mock Token สำหรับ Demo แต่มี Middleware พร้อมเชื่อมต่อ Firebase Auth จริง"

Q4: "API มีกี่ตัว?"
A4: "ทั้งหมด 14 endpoints แบ่งเป็น 5 กลุ่ม: Auth (3), Users (2), Tasks (4), Games (3), Sleep (3)"

Q5: "ทดสอบยังไง?"
A5: "มี Automated Testing Script ที่ทดสอบทุก endpoint อัตโนมัติ"

Q6: "Error Handling มีไหม?"
A6: "มีครับ ส่ง Status Code ที่ถูกต้อง และ Error Message ที่ชัดเจน"

Q7: "Scalable หรือไม่?"
A7: "ใช่ครับ ออกแบบแบบ Modular แยก Routes, Middleware, และ Database Layer"

Q8: "Security มีอะไรบ้าง?"
A8: "Token Verification, User-specific Data Access, Input Validation, CORS Protection"
